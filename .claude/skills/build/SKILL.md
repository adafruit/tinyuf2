# Build contract

`scripts/check_build.py` is the entry point for verifying a change; every agent and workflow that does so calls it rather than composing cmake or idf.py lines. A debug build for a probe session is not verification and uses the port's own build directly (below).

```bash
B=.claude/skills/build/scripts/check_build.py
python3 $B --scope <changed paths or dirs>     # boards a change affects
python3 $B --base origin/master                 # same, from the branch diff
python3 $B --base origin/master --worktree      # same, plus uncommitted and untracked changes
python3 $B --select-only (--scope ... | --base REF [--worktree] | --diff-file FILE) [--hil-config ROSTER]   # the selection alone
python3 $B --board feather_stm32f405_express [--board ...]
python3 $B --board lpcxpresso55s69 -D LOG=2     # a define, passed to the board's backend
python3 $B ... --shared                         # keep cmake-build/cmake-build-<board>, the dir a flash or HIL run uses
python3 $B --board imxrt1064_evk --shared --hil-config test/hil/ci.json   # the HIL's receipt
python3 $B --board metro_m7_1011 --shared --hil-config test/hil/local.json --variant update -D 'CFLAGS_CLI=-UUF2_VERSION -DUF2_VERSION="hil-update"'   # a second record beside it
python3 $B ... --idf local                      # exported ESP-IDF instead of CI's docker image
```

The last stdout line is JSON. An agent acts on `pass`; `firstError`, and `error` on exit 2, naming the cause or the remedy; `boards[]` (`status` `ok`, `failed` or `error`, `log`, `artifacts`, `notImplemented`); `built`, the artifacts of `--shared` roots, the only ones kept after a pass, with each one's hash in `boards[].sha256`; `nothingToBuild` and `uncovered`, each path with its reason; and `idf.matchesCi`. `input` and `defines` record what a build used (HEAD, `dirty`, submodule and `get_deps` dependency commits, `dirtyInputs` for any of those with local changes, `inputsDirtiedByBuild` for any that changed or moved while building, `.` for the checkout itself): the HIL contract binds firmware to this record. `paths` gives every changed path's `rule` and `reason`, the answer to why a path selected what it did. Exit 0 pass, 1 a build, self-test or test failed, 2 usage, resolution or a missing prerequisite, 3 an uncovered path; 2 outranks 1, and 1 outranks 3. `-v` streams the build to stderr; each build's log is `<buildDir>/check_build.log`.

`--shared` also keeps the bootloader ELF for debugging, at `cmake-build/cmake-build-<board>/tinyuf2.elf`.

`--select-only` prints the selection (`build.{ports,builds,ghostfat,tests,paths,ci}`) and stops before any toolchain check: what any agent or CI step reads for "what does this change affect". With `--hil-config <the host's roster>` it adds `hil.{boards,full,uncovered}`: the roster boards the change puts under the HIL battery, selected by the same rules and the same backend per port as CI's, without the CodeQL build; and as uncovered each selected port with no roster board on this host and each app source (`apps/`, `ports/<port>/apps/`) but `dfu_runtime`'s, which the battery never runs. `dfu_runtime` selects the Espressif roster boards of the ports that build it, and is uncovered once for each port that builds it without one.

## Reporting

An agent that reports `buildOk` and `notes` (agentrc's `code-writer`) maps the JSON this way: `buildOk` is `pass`. A pass with no board, self-test or test run is "nothing to build": quote each `nothingToBuild` reason in `notes`, so nobody mistakes it for a build that ran. Exit 3 is `buildOk` false with each `uncovered` reason quoted verbatim: that path is firmware no CI build compiles, and a human adds coverage or accepts the gap. Exit 1 or 2 quotes `firstError` (and `error`). A pass on `--idf local` whose `idf.matchesCi` is false is supplemental evidence only: say so in `notes`; acceptance needs CI's IDF.

## Judgment

- **Selection is the script's**, first match per path, and `paths[].reason` says why. A mixed change takes the union, and an uncovered path fails it whatever else built. The policy behind the rules:
  - A change to a port, board, app or dependency builds the boards that compile it: a board's own files that board; other port files the port's `REPRESENTATIVES` (rig boards first, every ESP32 target the port's boards use, both i.MX RT10xx and RT1170); an app or dependency the representatives of the ports whose CI backend compiles it.
  - Shared code (`src/`, `lib/`, the shared build files) and anything unclassified builds every port's representatives, plus the ghostfat self-test when a ghostfat input changed.
  - A change to how boards build (this script, `build.yml`, `build_util.yml`, `ci_set_matrix.py`, `.github/actions/`) runs the contract's own tests and one smoke build per backend (cmake, ESP-IDF), and a change to this script the HIL battery on every roster board, since the HIL runner imports it; no firmware build verifies workflow syntax or orchestration. A change to the contract's tests, or to the code-size launcher and profile (`scripts/code_size*.py`), which no build or HIL run imports, runs the tests only.
  - A change to `codeql-buildscript.sh` builds its board (feather_stm32f405_express) with cmake, the backend CI gives its port.
  - No build reads a Makefile or `.mk`. Outside `lib/`, a deleted Makefile or `.mk` builds nothing, and one in the tree (a dangling symlink included) is refused (exit 2) rather than counted uncovered.
  - Firmware no CI build compiles is uncovered: `ports/template_port/`, `ports/ch32v20x/` (`--board ch32v203_r0_1v0` builds it on request with cmake, with a note), an app source no port's `CMakeLists.txt` builds.
  - Docs and agent, editor and repo metadata build nothing.
  - `build.ci` is CI's selection from the same rules (`.github/workflows/ci_set_matrix.py` reads it on a pull request): every board a change reaches, not the representatives. A board's own files select that board; a port file, dependency or shared app every board of the ports it reaches; a port app the boards that enable it. Shared code and a change to how boards build select `full`, every board and the ghostfat self-test; a ghostfat input the self-test alone. Tests, docs, CodeQL's build and uncovered paths select nothing.
- **Builds are CI's.** Each port builds the way `build.yml` builds it, ESP-IDF for espressif and cmake for every other port (`backend_of()`; `test_build.py` fails when `build.yml`'s ports and `REPRESENTATIVES` disagree), and the HIL's records use the same: cmake `-G Ninja -DCMAKE_BUILD_TYPE=MinSizeRel`, which also builds each app the port's `CMakeLists.txt` adds with `family_add_app()` as its own project; Espressif `idf.py build`. A board passes only with the artifacts its build must produce (`expected_artifacts()`): the bootloader images and the self-update and app images the port builds (its `family_add_app()` calls enabled for the board). A port without self-update is listed in `notImplemented`, which is not a failure.
- **`-D`** sets a CMake variable: `LOGGER=RTT` or `SWO` (either case); `LOG` (default 0) sets `TUF2_LOG` and `CFG_TUSB_DEBUG`; raw flags go through `CFLAGS_CLI`.
- **A HIL record** (`--board --shared --hil-config <roster>`) binds the build's own flash target to the board's roster flasher: a J-Link board is configured with `JLINK_OPTION=-USB <probe serial> -ExitOnError 1 -NoGui 1` (so `tinyuf2-jlink` selects that probe and fails non-zero), an ST-LINK board with `STLINK_SERIAL=<probe serial>` (so `tinyuf2-stlink` connects to that probe and writes the HEX), an openocd board with `OPENOCD=openocd`, `OPENOCD_SERIAL=<probe serial>` and `OPENOCD_VID_PID=<the roster's vid_pid>` (so `tinyuf2-openocd` runs the openocd on PATH, the one the provider runs, not the ADI fork's path, pinned to that probe, and programs the HEX), an esptool board's ESP-IDF `flash` target takes the tty at flash time, its bridge's or, for a USJ serial in MAC form (`AA:BB:CC:DD:EE:FF`), the chip's USB-Serial/JTAG's. The HIL never runs these targets: it passes the bound files to agentrc's flash provider, so the binding is a build-time check that the target and the roster agree. `boards[].flash` holds the target, the roster flasher, the target's generated command (checked to name that probe or chip and the build's own image), the configure defines that bound it and the build-tree files it reads (in `sha256` too); a rebuild and a HIL flash hold the build dir's lock (`<build dir>.lock`). `boards[].flashRoutes` binds each of the board's `tinyuf2.routes` (`openocd_esp`, `-f board/<chip>-builtin.cfg`, the USJ serial as `uid`) to the files the esptool binding hashed, for the same chip. Another flasher, a roster `args` other than `-device <name>`, `--chip <chip>` or `-f interface/cmsis-dap.cfg -f target/<target>.cfg`, an openocd flasher without one `vid_pid` pair, or a `-D` of `JLINK_OPTION`, `STLINK_SERIAL`, `OPENOCD`, `OPENOCD_SERIAL`, `OPENOCD_VID_PID`, `OPENOCD_OPTION` or `ESPPORT` is refused. ESP-IDF's records go stale at the next commit (its `git describe` dependency re-runs CMake), so rebuild the record on the commit under test.
- **`--variant NAME`** (with `--board` and `--shared`) builds into `cmake-build/cmake-build-<board>-variant-NAME`, so a second record of the same checkout, made different by its `-D`, sits beside the plain one; the record and its row carry `variant`. It is the HIL update battery's distinguishable bootloader (hil-contract Execution, Update): no CI evidence.
- **ESP-IDF** builds in CI's image, `espressif/idf:<build.yml's toolchain_version>`, through docker by default; a missing image is exit 2 naming the `docker pull`. Its container (`tinyuf2-build-<pid>-<hex>`) is removed when the build is interrupted or its client killed, else the log gives its `docker rm -f`; a SIGKILL of check_build can leave it. `--idf local` uses the exported IDF and records its version and `matchesCi`: evidence from a different IDF is supplemental, not acceptance.
- **ghostfat** builds each `ports/test_ghostfat/boards/*` config natively with cmake and runs its `selftest` target, which compares the generated image with the config's known-good one, in the private dir, one config at a time: `huge` needs about 3 GiB of disk while it runs. A passing config's dir is removed; a failing one keeps its log.
- **Private dirs for parallel agents.** Each build starts from an empty `cmake-build/cmake-build-agent-<pid>-<board>` and is removed when it passes (`removed`; its `artifacts` say what it produced, nothing is left to flash); a failed one is kept for its log. Nothing is written into the source tree: cmake and idf take `-DARTIFACT_PATH=<dir>/_bin`. `--shared` rebuilds `cmake-build/cmake-build-<board>` from clean and keeps it for flashing; it needs exclusive ownership of that board.
- **Dependencies are never fetched here.** `lib/tinyusb`, `lib/uf2` and `lib/agentrc` (the HIL lock helper the contract tests load) are submodules (`git submodule update --init lib/tinyusb lib/uf2 lib/agentrc`); a port's `tools/get_deps.py` rows must exist. In a worktree, symlink them from the primary checkout (CLAUDE.md); `get_deps.py` refuses to update a symlinked dependency path.
- **Debug builds** for a probe session use the port's build directly: `cmake -B <dir> -G Ninja -DBOARD=<b> -DCMAKE_BUILD_TYPE=Debug -DLOG=2 -DLOGGER=RTT ports/<port>` (`-Og` on GCC; `LOGGER=SWO` too; only `RTT` adds the RTT sources). Debug with logging can overflow a small bootloader region: feather_stm32f405_express's 31 KB takes `LOG=1 LOGGER=RTT` (99%) but not `LOG=2`; lower `LOG` or keep MinSizeRel there. Flash and erase targets: README.md's Flash table; Espressif `idf.py -C ports/espressif -DBOARD=<b> flash`. On ports built with `-flto`, a `static` function may be inlined and absent as a standalone symbol; debug its caller, or use a local instrumented build that marks the function `__attribute__((noinline))`.
- **Printing a command is not verification.** A verdict is the JSON of a run that happened; an agent that cannot run the script reports the build as not run.

## Code size

agentrc's `code-size` skill holds the commands, engines and how to read a report; this section is TinyUF2's half. The launcher is `python3 .claude/skills/build/scripts/code_size.py <report|diff>`: agentrc's engine from `lib/agentrc` at the pin HEAD records (`check_agentrc_pin`; off it, exit 2), run with `scripts/code_size_profile.py`. It sizes a board's bootloader, `tinyuf2.elf`. For historical-base compatibility (comparisons against refs built with make), a base built with make gets `tinyuf2.elf` and its map linked to make's `ports/<port>/tinyuf2-<board>.elf`, so the two trees' bootloaders pair as one elf. Apps and self-update are built, never sized. There are no examples (`-e` is refused) and no CI snapshots: `diff` always builds its base here (by default `origin/master`'s tip, so fetch first), and `snapshot`, `compare` and `--base-source ci` are refused.

- Each tree builds through its own `check_build.py --board B --build-dir DIR`, the way CI builds the port, into `cmake-build/code-size/<board>/build` (base: `base`); a base whose `check_build.py` predates `--build-dir` builds with `--shared` inside its temporary worktree, which only that worktree sees, and is refused on Windows, where `--shared`'s lock is unavailable. With `idf.py` on PATH both trees use `--idf local`, else CI's docker image.
- The base worktree (`cmake-build/code-size/_worktree`) gets each submodule checked out at the base's own pin, borrowing the objects, shallow boundary and refs of this checkout's (a pin a `--depth 1` submodule fetched by SHA counts, and its `git describe`, which the bootloader embeds, is unchanged), so a `lib/tinyusb` bump's own size change is in the diff; a pin this checkout's submodule has not fetched is refused naming `git -C <submodule> fetch --depth 1 origin <pin>` (without `--depth 1` where the submodule is a full clone, which it would make shallow), an uninitialised submodule naming `git submodule update --init`. Each dependency dir its own `tools/get_deps.py` lists as mandatory, or for a port the base keeps a sized board in, is linked from this checkout's where that is a clean checkout of the base's pin (no modified, untracked or ignored file), else checked out at the base's pin borrowing its objects, so neither a dependency bump's size change nor a local edit to it is hidden; a pin it has not fetched is refused naming the same fetch, and a dependency dir that is no git checkout naming `tools/get_deps.py`. Any other dependency is linked as it is, because no sized build reads it. A submodule borrowing objects from outside the checkout (`git clone --reference`) breaks the docker build of the base: `git -C <submodule> repack -a -d` and remove its `objects/info/alternates`.
- `--engine sections` (the default) is the elf's allocated-section Flash/RAM, per section: the number a bootloader-region budget is about. Per-file attribution of `src/` and `ports/` is `--engine bloaty` (bloaty on PATH): `daisy_seed`'s cmake build, without LTO, keeps its compile units, `feather_stm32f405_express`'s cmake LTO build does not. membrowse and linkermap are not offered.
- The bootloader embeds `git describe`, so two trees at different commits, or one dirty, differ by that string's length in `.rodata`/`.text` whatever the change.
